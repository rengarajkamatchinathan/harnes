# Write a spec

1. Find the problem, the audience and the decisions already made. Ask one short question only if the answer changes the spec's direction.
2. Use this outline, dropping sections that do not apply:
   - **Summary**: two or three sentences.
   - **Goals** and **non-goals**.
   - **Background**: only what a reader needs.
   - **Design**: the approach, data shapes, interfaces and flows. Prefer tables and short lists.
   - **Alternatives considered**, each with the reason it was not chosen.
   - **Risks and open questions.**
   - **Rollout and testing.**
3. Write decisions as decisions ("X uses Y"), not possibilities. Mark assumptions explicitly.
4. Keep it as short as the subject allows. Use exact names, numbers and units.
